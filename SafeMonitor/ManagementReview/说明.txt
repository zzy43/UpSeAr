管理复盘 · 事件协同闭环管理
====================================================================

一、这是什么
--------------------------------------------------------------------
和安全审核（SafetyAudit/work.html）、法定自查（CheckQuestion/check.html）
**是三套不同的系统**，从轮播首页点「管理评审（Management Evaluation）」
那一页的信息面板进来。

它解决的是这个问题：

    · 安监部牵头，运技部、飞行部配合；
    · 把**非 396 事件**里的**重点 QAR 项目**捞出来，一条一条盯；
    · 每个项目要走完**六步闭环**：

        调查 → 分析 → 讲评 → 措施 → 改进 → 督促
        (安监/运技)(运技部)(运技部)(飞行部)(飞行部)(安监部)

      括号里是**新建项目时的默认负责部门**（每一步都能单独改）。
      其中「调查」按级别分：**普通 / 重要 → 运技部，严重 → 安监部**
      （见 review-config.js 的 LEVEL_FIRST_STAGE_DEPT）。

    · 每一步都记：状态（未开始 / 进行中 / 已完成）、负责部门、办理人、
      日期、情况说明、附件（交付 / 取证材料）；
    · 六步全部完成，这个项目就算「已闭环」。

界面上就两件事：**左边选项目**，**右边看它的六步闭环**；
右上角「▦ 六步看板 / ▤ 项目闭环」可以切成看板，六个项目状态一目了然。


二、文件结构
--------------------------------------------------------------------
    ManagementReview/
      review.html           页面（唯一入口）
      js/
        review-config.js    配置：云端地址、协作部门、六步定义、
                            项目级别/来源、默认项目（**只想改内容就改这个文件**）
        review-core.js      基础层：状态、小工具、云端读写（含自动上传）、
                            弹层、轻提示、亮/暗主题、背景海报
        review-items.js     项目闭环：左边项目列表 + 右边六步详情 / 编辑
        review-board.js     六步看板：每个项目摆进它当前所处的那一步
        review-main.js      启动与事件绑定
      css/
        review-base.css     设计变量、基础、海报背景、顶栏、按钮、小牌子
        review-parts.css    弹层、表单、附件区、轻提示
        review-app.css      两栏布局、项目列表、六步卡片、看板
        review-light.css    亮色模式（整段覆盖暗色的部分）

加载顺序不能乱：config → core → items → board → main。
样式加载顺序也不能乱：base → parts → app → light。


三、数据存在哪（★ 独立目录，不跟别的系统混）
--------------------------------------------------------------------
云端上给这个系统**单独开了一个目录** ManagementReview/：

    数据文件：
      https://safety-audit-system.oss-cn-hangzhou.aliyuncs.com/ManagementReview/review.json

    交付 / 取证附件（页面上传时自动放这儿）：
      https://safety-audit-system.oss-cn-hangzhou.aliyuncs.com/ManagementReview/文件/20261010-101530-调查报告.pdf

和安全审核（SafetyAudit/plan.json）、法定自查（CheckQuestion/check.json）
**完全分开**，互不影响。地址在 js/review-config.js 的
OSS_BASE_URL / OSS_JSON_FILE 里改。

    · **第一次打开时云端还没有这个文件**，这是正常的 —— 右上角会显示
      「待首次上传」，这时页面用的是配置里的默认项目。
    · 你随便改一下（加个项目、填一步），停手约 0.8 秒后会自动上传，
      文件就建出来了（正常时那个角标会藏起来）。
    · 之后所有改动都是自动上传的，不用手动导出/上传。
    · 想备份：「⋯ → ⤓ 导出 JSON」下载一份；想恢复：「⋯ → ⇪ 导入 JSON」粘回去。
    · 想拿去汇报/统计：「⋯ → ⤓ 导出 Excel」，选导出「当前项目」或「全部项目」。
    · ⚠ 数据文件必须是**公开可读可写**的（和其他系统同一套配置就行）。
    · 首屏会先把**上次读到的数据**秒画一屏（浏览器缓存），真正的数据一到就盖掉；
      读不到云端时若手里有缓存，就用缓存顶着并且只读。


四、数据结构（review.json 的内容）
--------------------------------------------------------------------
    {
      "theme": "Management Evaluation",
      "title": "管理复盘 · 事件协同闭环管理",
      "updated": "2026-10-10 10:15",

      "departments": [                       // 协作部门（第一个是牵头部门）
        { "name": "安监部", "color": "#3FA796", "note": "牵头" },
        { "name": "运技部", "color": "#5B8FF9", "note": "配合" },
        { "name": "飞行部", "color": "#9B7BE8", "note": "配合" }
      ],

      "items": [                             // 一个个 QAR 项目
        {
          "id": "qar-xxx",                   // 唯一标识，别重复
          "no": "重要-2026-01",              // 项目编号（新建时自动生成，可改）
          "title": "起飞机段俯仰配平超限（非 396 事件）",
          "level": "重要",                    // 只能是 LEVELS 里的值：普通 / 重要 / 严重
          "source": "QAR/FOQA",              // 只能是 SOURCES 里的值
          "date": "2026-09-12",              // 事件日期 YYYY-MM-DD
          "flight": "MU5123",                // 航班号（可空）
          "aircraft": "B-1234",              // 机号（可空）
          "lead": "安监部",                  // 牵头部门
          "owner": "陈吉龙",                 // 负责人（可空）
          "desc": "事件描述……",              // 说明（可空）
          "status": "open",                  // open=进行中 / done=已闭环
          "stages": [                        // 六步，按 STAGES 的顺序
            { "key": "investigate", "status": "done", "date": "2026-09-15",
              "dept": "运技部",
              "notes": [                     // 情况说明，**可以多条**
                { "dept": "运技部", "by": "陈吉龙", "date": "2026-09-15",
                  "text": "已核实事件经过……",
                  "files": [ { "name": "调查报告.pdf", "url": "https://…", "size": 1234 } ] },
                { "dept": "飞行部", "by": "陈震", "date": "2026-09-16",
                  "text": "机组补充说明……", "files": [] }
              ] },
            { "key": "analyze", "status": "doing", "dept": "运技部",
              "notes": [ { "dept": "运技部", "by": "陈震", "text": "……", "files": [] } ] },
            { "key": "review",    "status": "todo", "dept": "运技部", "notes": [] },
            { "key": "measure",   "status": "todo", "dept": "飞行部", "notes": [] },
            { "key": "improve",   "status": "todo", "dept": "飞行部", "notes": [] },
            { "key": "supervise", "status": "todo", "dept": "安监部", "notes": [] }
          ]
        }
      ]
    }

    · stages[].key 必须等于 review-config.js 的 STAGES 里某个 key
      （investigate / analyze / review / measure / improve / supervise），
      顺序按 STAGES 走，写乱也没关系，读进来会重排。
    · stages[].status：todo = 未开始 / doing = 进行中 / done = 已完成。
    · stages[].notes 是**情况说明，可以多条**：每条 { dept, by, date, text, files }，
      部门 / 办理人 / 日期 / 附件都各自独立 —— 比如运技部一条（带它的材料）、
      飞行部一条（带它的材料）。files 结构 { name, url, size }，
      页面上传时自动生成，文件名前面加时间戳防重名。
    · items[].status **不用手写**：六步全 done 时页面会自动把它算成 done
      （已闭环）；想强制标记也能手写 "done"。


五、怎么用
--------------------------------------------------------------------
1. **新建项目**：右上角「⋯ → ＋ 新建项目」，或左边栏底部「＋ 新建项目」。
   **编号自动生成**（如 `重要-2026-01`）：前缀跟级别走（普通 → 普通，重要 → 重要，严重 → 严重），
   年份取当前年（到 2027 年就自动变 2027），序号在同前缀同年的已有编号里顺排、不重复；
   **级别一改编号跟着换**，也可以直接手改成别的（手改后就不再自动跟级别变）。
   再填名称、来源、事件日期、航班/机号、牵头部门、负责人、说明。
   建好后自动生成六步（都是「未开始」）。

2. **推进某一步**：右边点那一步的卡片（或卡片右上角的「编辑」），
   填状态、完成/更新日期、负责部门，再写**情况说明**（**可以多条** ——
   点「＋ 增加情况说明」，每条单独选部门 / 填办理人 / 填日期，比如运技部一条、
   飞行部一条）；**附件挂在各自的情况说明下**（每条右下「＋ 附件」，也能把文件
   直接拖进去）。点「保存」。附件是**选好就立刻上传**的，点「保存」才挂上去。

3. **看整体进度**：项目头部有进度条（6 步完成了几步）；
   左边每个项目下面也有六个小圆点（灰=未开始，金=进行中，绿=已完成）。

4. **六步看板**：右上角「▦ 六步看板」，项目按**当前所处的那一步**各归到一列；
   六步全完成的落到**下面单独一块「✓ 已闭环」**里（会换行排成多列，项目多了也不挤）。
   点卡片回到项目闭环视图。

5. **筛选**：左边有搜索框和级别小牌子（全部 / 普通 / 重要 / 严重），
   可以只看某一级别的项目。

6. **删项目**：右边头部「🗑 删除」。

6.1 **导出 Excel**：右上角「⋯ → ⤓ 导出 Excel」，弹框里选
   「当前项目」（只导右边正在看的那个）或「全部项目」。
   导出的是 **.xlsx**，里面三张表：
     · 「项目总览」—— 一个项目一行（编号 / 级别 / 名称 / 来源 / 日期 / 航班 / 机号 /
       牵头部门 / 负责人 / 状态 / 闭环进度 / 当前步骤 / 情况说明条数 / 附件数）；
     · 「六步明细」—— 一个项目六行（步骤 / 状态 / 主负责部门 / 更新完成日期）；
     · 「情况说明明细」—— 一条情况说明一行（含部门 / 办理人 / 日期 / 内容 / 附件名）。
   ★ 这个 xlsx 是**浏览器里现拼的**（没引任何库，断网也能用），见
      js/review-core.js 的 downloadXlsx。

7. **亮/暗模式**：右上角「☀ 亮色 / ☾ 暗色」，记在浏览器里；
   第一次打开默认亮色。


六、想改东西改哪儿
--------------------------------------------------------------------
    · 改部门 / 六步名称 / 级别 / 来源 / 默认项目 → js/review-config.js
    · 改项目列表和六步卡片的画法 → js/review-items.js + css/review-app.css
    · 改看板 → js/review-board.js + css/review-app.css 的看板一节
    · 改配色（两套主题的变量）→ css/review-base.css 的 :root
      和 css/review-light.css 开头
    · 改云端目录 / 文件名 → js/review-config.js 的 OSS_BASE_URL / OSS_JSON_FILE
