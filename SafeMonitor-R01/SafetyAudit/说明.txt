【安全审核 · 工作系统】使用说明
====================================================================

一、本地文件（就是这个文件夹）
    SafetyAudit/
      work.html              页面入口（从轮播页点左侧信息面板打开，也可直接双击打开）
      plan.json              起始数据模板（上传到 OSS 后就能看到真实数据）
      说明.txt               本文件
      css/                   样式拆成 5 份，按功能分
        work-base.css        ①基础层：设计变量、基础/重置、海报背景、顶栏工具栏
        work-board.css       ②表格层：表格容器、日期表头、项目列、单元格（含责任人牌子）、小屏适配
        work-calendar.css    ③日历模式：月历网格、节假日标记、安排小卡片、选项目弹层
        work-parts.css       ④组件层：按钮、角标、弹层、表单、轻提示、文字描边
        work-light.css       ⑤亮色模式（整段覆盖暗色变量，含日历的）
      js/                    逻辑拆成 8 份，按功能分
        work-holidays.js     法定节假日 / 调休数据（只给日历模式区分放假 / 补班用）
        work-config.js       配置：OSS 地址、数据文件名、时间轴、表格尺寸、字体、责任人名单
        work-core.js         ①基础层：工具函数、状态、读 OSS/清洗数据、自动保存、弹层、字体、主题
        work-board.js        ②表格层：渲染表格、定位到今天
        work-edit.js         ③编辑层：填安排、增删改工作项目、责任人拖放
        work-io.js           ④数据进出：导出/导入 JSON、数据源角标
        work-calendar.js     ⑤日历模式：月历视图、翻月、给某天排活
        work-main.js         ⑥启动与事件（必须最后加载）
      _gen_holidays.py       小脚本：重新生成 js/work-holidays.js（要用 python 跑）
    注意：css 和 js 的加载顺序不能乱（节假日 → 配置 → 基础 → 表格 → 编辑 → 数据 → 日历 → 启动）。
    只要改外观/行为，一般改 work-config.js（配置）、work-light.css（亮色）、work-board.css（表格）就够。

二、数据放在 OSS 上
    目录：https://safety-audit-system.oss-cn-hangzhou.aliyuncs.com/SafetyAudit/
    排期数据：SafetyAudit/plan.json
    以后的资料（照片、附件等）都放这个目录下的子目录里，例如：
        SafetyAudit/图片/…
        SafetyAudit/附件/…
    页面里写相对路径即可，js/work-core.js 的 ossAsset() 会自动补成 OSS 完整地址。

    ★ **还有一份和「法定自查」（CheckQuestion）共用的文件（2026-09-21 加的）**：
        https://safety-audit-system.oss-cn-hangzhou.aliyuncs.com/审核员.json
      就是那四个责任人（名字 + 底色 + 字色 + 日历里的那个单字），
      **两套系统都读它、也都写它** —— 所以一边改了名字/颜色/单字，
      另一边刷新后就是同一套；一边加了人/删了人，另一边也跟着变。
      放在 bucket **根目录**：SafetyAudit/ 和 CheckQuestion/ 是两个独立目录，
      根目录才是它们共同的地方。
      · 文件名/地址在 js/work-config.js 的 OSS_ROSTER_FILE / OSS_ROSTER_URL 里改
        （**两边的配置都要改**，否则对不上）；
      · 结构：`{ "updated": "…", "auditors": [ { "name", "color", "ink", "short" } ] }`；
      · **没这个文件也能正常用**（第一次改样式 / 加人才会把它建出来），
        这时就用 plan.json 的 assignees（没有就用 work-config.js 的 ASSIGNEES）；
      · ⚠ 但**一旦这个文件存在了，就以它为准** —— 也就是说，
        往 plan.json 里手写 assignees 是没用的（两边都听 审核员.json）。

三、日常操作流程（全自动，不用再碰 OSS 控制台）
    1. 打开页面：自动从 OSS 读 SafetyAudit/plan.json；
    2. 点格子填安排、点左侧项目名改名称/副标题、点「＋ 工作项目」加行；
       左上角「工作项目 \ 日期」那一格的右边也有一个小「＋」，鼠标不用跑回顶部就能加项目；
       点已有内容的格子打开的弹层里，最上面是**年 / 月 / 日三个小框**，
       多数时候只改「日」：点进去会自动全选，直接打数字就换掉了，
       年填满 4 位自动跳到月、月填满 2 位跳到日；改完保存就把这条安排搬到新的那天
       （目标那天已经有安排会先问一句要不要覆盖）；
       弹层里**正文、详细内容、相关文件一次填完**（2026-09-21 改的，见第十二节）：
       以前底部那个「📄 详细 / 文件」按钮已经去掉了；
    3. 每改一次，停手约 0.8 秒就自动上传覆盖回 OSS，右上角依次显示：
       「待保存…」→「保存中…」→「已保存 10:30:12」；
    4. 万一保存失败，会显示红色的「保存失败，点此重试」，点一下重传。
    ⚡ **打开速度（2026-09-21 提速，用户报「进入的时候加载很长时间，而且有时候加载不进去」）**：
      · **两个请求同时发**：plan.json 和共用名单 审核员.json 以前是**串着**的
        （实测 plan.json 102ms 走完，审核员.json 才开始），白等一个完整来回；
      · **首屏先画上次的数据**：上次读到的存一份在 localStorage 的
        `safemonitor:work:cache`，打开先拿它秒画，真数据一到就盖掉
        （stale-while-revalidate）；画缓存那一下**只读**（`state.cacheOnly`，
        `canWrite()` 里判了）—— 不然一个快速操作就可能把旧数据整份写回 OSS；
      · **读不到就重试一次**（等 600ms；4xx 不重试）：以前网上抖一下就直接退示例数据
         + 暂停上传，得手动刷新；现在多试一次，而且**有缓存就用缓存顶着**
        （只读 + 角标写「读取失败」），不再直接把你的数据换成示例数据；
      · 实现都在 js/work-core.js 的 loadAll() / paintData() / saveCache()。
      想法把「真正第一次打开」的样子看一遍：删掉 `safemonitor:work:cache` 这个键。
    备注：
    · 打开页面时如果没读到 OSS 数据（断网、文件不存在），会自动暂停上传并显示
      「自动上传已暂停」——这是防止拿示例数据把 OSS 上的真数据覆盖掉；
    · 「导出 JSON」按钮还在，只作备份/手工兜底用，平时不需要。

四、OSS 设置检查结果（2026-09-19 实测）
    1. 匿名读取：✔ 正常（GET plan.json 返回 200，application/json）。
    2. 匿名写入：✔ 正常（匿名 PUT 返回 200）——bucket 现在是「公共读写」，
       所以页面不需要任何密钥就能直接保存，改完自动覆盖 plan.json。
    3. 跨域 CORS：✔ 已配好（Access-Control-Allow-Origin: *，预检允许
       GET/POST/PUT/HEAD，允许 authorization/content-type/date 头）。
    4. 防盗链：没开，本地双击打开也能读写。
    5. ⚠ 提醒：公共读写意味着任何拿到这个地址的人都能覆盖/删除里面的东西。
       你说里面没什么重要的，那可以接受；以后若放敏感资料，就把 bucket 改成「公共读」，
       再建一个只授权该 bucket 的 RAM 子账号，把 AK/SK 填进 js/work-config.js
       （那就需要额外实现签名上传，现在这版是免密钥的直传）。
    6. 缓存：页面读数据时自动加了 ?_t=时间戳，不会拿到旧缓存。

五、plan.json 格式
    {
      "theme": "Safety Audit",
      "title": "安全审核 · 工作计划",
      "updated": "2026-09-19",
      "range": { "start": "2026-09-01", "end": "2026-11-30" },
      "assignees": [
        { "name": "景志详", "color": "#E8688A", "short": "景" }
      ],
      // ⚠ 名单的真实住处是共用的 审核员.json（见第二节）；
      //   这里只是那份文件还没建出来时的初始值 / 备份。
      "items": [
        { "id": "plan", "name": "年度审核计划编制与发布", "subtitle": "9 月批次",
          "pinned": true }
      ],
      "tasks": [
        { "item": "plan", "date": "2026-09-22", "text": "完成初稿评审", "done": false,
          "assignees": ["景志详", "方乔"],
          "detail": "详细内容（弹层「详细」里填的，可多行）",
          "files": [{ "name": "审核计划.pdf", "url": "https://…/SafetyAudit/文件/….pdf", "size": 123456 }] }
      ]
    }
    · items = 行（工作项目），tasks = 格子（某项目在某天的安排）；
      （⚠ 表格第一行那条「空白行」**不在这里** —— 它只是画出来的占位，
       见第八节 8.4；用户在上面真干活了才会变成一条真的 items）
    · items[].pinned = 置顶（2026-09-21 加，见第九节 6.2）：只有置顶的才写这个字段，
      置顶的都排在数组最前面；
    · items 的**顺序就是表格里显示的顺序**（不另存序号）：置顶的在最前、
      还没排活的紧跟其后、然后按「临近日期」排（见第九节 6.3）、已完成的沉底；
    · items[].manual = 用户拖动行头手动排过序（只有拖过的才写这个字段）：
      这一项不再参与按日期的自动排序，就留在用户放的位置上；
    · items[].subtitle 是副标题（在项目弹层里填），会显示在项目名下面一行，不填就不占位置；
      责任人那一栏已经去掉了 —— 谁负责哪天是靠把名字牌子拖到格子上表示的，
      （老数据里这个字段叫 owner，现在也认，存一次之后就自动改成 subtitle）；
    · tasks[].item 必须等于某个 items[].id，date 用 YYYY-MM-DD；
    · tasks[].assignees 是责任人，数组里的第一个人是主责任人（页面上不特别标示）；
      没写就是未指定；老格式写单个字符串 "assignee": "景志详" 也认；
    · tasks[].detail 是详细内容，tasks[].files 是这条安排的相关附件
      （名字 / OSS 地址 / 字节数）；两个都在那个「填安排」弹层里编辑和上传（第十二节）；
    · assignees（顶层那个）是责任人名单，页面上点「＋」加过人才会写进来；
      没这个字段时用 js/work-config.js 里的 ASSIGNEES 当默认名单。
      （⚠ 2026-09-21 起名单的**真实住处**是共用的 审核员.json，见第二节；
        这里只是备份 —— 共享文件存在时以它为准。）
      `short` 是**日历格子里显示的那一个字**（没写就取名字第一个字），
      `ink` 是牌子上的字色（没写用 CSS 的 --chip-ink），
      两个都在「⋯ → 🎨 编辑责任人样式」里改，见第七节 1.2。
    · range 可以省略，省略时按「今天前 8 天 ~ 后 15 天」自动铺日期列
      （在 js/work-config.js 的 DAYS_BACK / DAYS_FORWARD 改；
       只要 plan.json 里写了 range，就以 range 为准，那里也要一起删掉才生效）。

七、责任人怎么用
    1. 工具栏**上方**常驻一条责任人带（打开页面就在），四个名字排成一行
       （名字、颜色、先后顺序的**默认值**在 js/work-config.js 的 ASSIGNEES 里改，
       当前顺序是：景志详 / 李孟清 / 方乔 / 朱震宇，颜色深一点 + 白字最好看）；
       点工具栏的「👤 责任人」可以把它收起来，再点一下又展开。
       这条带子背景和边框都是透明的（只有彩色名字浮在页面上）；
       它有点别于「⋯」那种悬浮菜单：点别处不会自己收，只有再点按钮才收
       （不然刚拖完一个名字它就没了）；
       1.1 **最右边有一个「＋」**：点它新增责任人，填名字 + 选颜色（有取色器，
       也有 7 个常用色块可以一点就换）；加完自动展开这条带子。
       名单事实上存在**两套系统共用的 审核员.json**（见第二节），
       所以**这边加的人，法定自查那边刷新一下也会出现**（反过来也一样）。
       plan.json 里的 `assignees` 也会跟着一起改（当备份）——
       ⚠ 共享文件存在时，两边都**以 审核员.json 为准**，往 plan.json 里
       手写 assignees 是不生效的；
       1.2 **单字、底色、字色都可以自己定**（2026-09-21 加）：工具栏最右边
       「⋯ → 🎨 编辑责任人样式」，每个人一行：
         · 左边那个小牌子就是**日历格子里看到的样子**（一格一个字）；
         · **单字** —— 默认取名字第一个字（朱震宇 → 朱），可以改成任意一个字
           （比如习惯用「宇」，或者用个花名「泰」）；留空/删掉就是回到取首字；
         · **底色** —— 名字牌子的颜色，表格、日历、弹层里都跟着变；
         · **字色** —— 牌子上那个字的颜色（2026-09-21 加）；不填就一直用
           CSS 里的 `--chip-ink`（那道亮蓝）。各处的牌子走的都是
           work-core.js 的 `assigneeStyle(name)`，底色字色由它拼出来；
         · 改哪个输入框左边牌子马上跟着变；点「保存」才生效；
           ⚠ 「恢复默认」按用户要求**已经去掉了**（2026-09-21）：弹层里只剩 取消 / 保存。
             想回到 work-config.js 那套，就把单字清空、颜色改成那几个值 ——
             或者把 审核员.json 删了（会回落成 plan.json / work-config.js 里的名单）。
       ⚠ 这一份样式也是**和安全审核共用的**（存在 审核员.json，见第二节）——
         在这边改，法定自查那边（菜单里叫「⟳ 编辑样式」）刷新后也是同一套。
       ⚠ 表格里的名字牌（`.cell-owner`）显示的仍是**全名**，只有日历格子用单字；
         法定自查那张表也一样，都显示全名（那个单字就只为日历格子服务）。
    2. 把一个牌子拖到某天的格子上松手，那个人就排到这天了；
       格子空的会自动建一条「只有责任人、没有内容」的安排；
    3. **一个格子可以拖好几个人**，先拖的排在前面，**第一个人是主责任人**（页面上不特别标示）；
       同一个牌子不会重复加；点格子里的某个名字 = 只把这个人在这一天移除；
       要一次清空，就把格子里的名字逐个点掉（名字全没了、内容也空的话这条安排会一起删）；
    4. 单元格里会显示彩色名字牌（超过一行会自动换行），数据存在 plan.json 的
       tasks[].assignees 数组里，一起自动上传 OSS。
    5. **点名字牌子 = 「只看」，可以多选几个人**（2026-09-21 起支持多选）：
       · 点一个名字 = 把他加进名单；**再点一下这个已选中的名字 = 把他移出去**；
         选了几个，工具栏按钮就写「👤 只看 景志详、方乔」，选中的牌子带白圈 + ✕；
       · 选中的名字牌子后面会多出一个「✕ 看全部」，点它一次清空、显示全部；
       · **✓ 名单里的人的格子** → 高亮（蓝色底 + 蓝框），一眼看到活在哪几天；
       · **✕ 别人的格子** → 内容直接**藏起来**，只剩一个点不动的空格
         （格子必须留着占位，少画一格整张表就错位了）；
       · **✕ 没有他们活的工作项目** → 整行**不画**（不是压暗，是直接不显示）；
       · 日历模式下同理：不在名单里的安排卡片也不画，只留他们的；
       · 顶部（工具栏角标、日历那张统计行）和日历里的数字都只算名单里的人，
         还会写明「别人的安排已隐藏」；（底部那条统计 2026-09-21 已按用户要求去掉）
       有他们活的工作项目行会**自动提到表格最上面**，而且这个顺序会**一直保留**
       （取消只看，行也不会还原 —— 此时存的 items 顺序就是置顶后的）；
       · 注意：**每加一个人就会写一次 OSS**（就是上面那个「置顶」的副作用）；
         不想要这个行为的话，把 js/work-edit.js 里 setFilter() 中的
         `bringHitsToTop(state.filter)` 那一行注掉即可 —— 其余功能不受影响。
    6. 只看模式下不能拖动行头改顺序（这时只剩名单里的行）；退出只看后可以正常拖。
    6.2 **置顶（2026-09-21 加）**：重要的工作项目可以钉在最上面。
       · 怎么置顶：把鼠标移到那一行，点行头上那个 **▲**；再点一下取消。
         也可以在「编辑 / 新增工作项目」弹层里勾「置顶」。
         已置顶的行，项目名前面会多一个小 ▲（不用悬停也看得见，金色）。
       · **置顶的排在一起，在全部项目最前面** —— 但在首行那条空白行**下面**
         （空白行是渲染时画出来的，永远在所有项目之上）；置顶区里也是**后钉的在最上面**。
       · **拖拽跨过边界就自动加/去置顶**：把一行拖到置顶区里→自动置顶；
         拖到置顶区下面（普通区）→自动取消置顶；拖到最上面那条
         空白行的线上→置顶并放到第一行。会在提示里写明「（并置顶）」。
       · 「只看」也会**只在两个区内部重排**（置顶的一直在最前面），
         不会因为只看某个人就把普通项提到置顶项前面。
       · 存的是 `items[].pinned`（只有置顶的才写这个字段）。
       ⚠ 实现上**只用数组顺序表达**（拖拽、置顶都是在改数组顺序），没有单独的
         sort 函数 —— 只有下面 6.3 那个段内的自动排序。要改顺序就去
         work-edit.js 的 `placeItem() / togglePin() / moveItem() / reorder()`
         这几处（`bringHitsToTop()` 是「只看」用的，也在那儿）。
    6.3 **工作项目的自动排序（2026-09-21 加）**：不用手工拖，表格自己按「急不急」排。
       `reorder()`（work-edit.js）把 items 分成四段，**段内保持原来的先后**：

         ① 置顶区 —— 用户亲手钉的，永远最上面（首行那条空白行下面）；
         ② 还没排活的项目（一条安排都没有）—— 提到上端，紧跟在置顶区后面；
         ③ 有活、还没干完的 —— **按「临近日期」升序**：
             临近日期的定义 = 这个项目**还没完成的安排里最早的那一天**。
             日期是字符串，直接比大小就是按时间先后比，所以过去的日期天然小于
             未来 —— 9/22 的排在 9/24 前面，超期未完成的排在最前面（那本来就最急）。
             同一天的几项保持原来的先后（排序是稳定的）。
         ④ 已完成的项目 —— 沉到最下面（见 6.3.2）。

    6.3.1 **「除非用户手动移动排序」**：行头拖过一次，这个项目就打下 `manual` 标记，
       从此**不再参与 ③ 的日期排序**，就待在用户放的那个位置上（标记会存进
       items[].manual，刷新后照样）。
       · 只是**段内**不挪：它依然跟着自己的状态换段（比如把安排全删完，
         它会跟着进 ② 段）—— 「手动」保留的是同一段内部的先后。
       · 想让它重新回到自动排序？现在没有取消入口（没做，免得又多一个按钮）；
         真要清就把 OSS 里那一项上的 "manual": true 手删掉。
    6.3.2 **已完成的项目自动沉到最下面**：一个工作项目名下的安排**全部**勾了
       「已完成」（且至少有一条），这一行就沉到表格最后。
       · 判定是「全部安排都 done」—— 一条安排都没有的空项目**不算**完成
         （那种进的是上面 ② 段）。
       · 底色标记：行头换成冷灰（暗色更暗的灰 / 亮色退成中性灰），项目名后面跟一个
         「（已完成）」的绿色文字标记；整行格子也压一层淡底色、内容透明度降到 0.62。
         ⚠ 项目名上**不加删除线**（用户 2026-09-21 明确要求换成那个括号标记）。
    6.3.3 **还没排活的项目**（② 段）的标记：行头换成**暖色底 + 左边一条 3px 金线**，
       悬停时右边会出现一个「待安排」小胶囊；整行格子压一层很淡的暖色。
       和上面那个冷灰的「已完成」一眼能分开。
    6.3.4 和置顶的关系：**已完成的项目不给置顶**（点行头的 ▲ 会提示一句，
       「编辑工作项目」弹层里的勾选框会置灰）；沉底时如果它还带着 pinned，
       会顺手把 pinned 清掉 —— 不然「置顶的 = 数组最前面那几个」这条不变量就破了。
       取消完成之后想再置顶，重点一下 ▲ 就行。
    6.3.5 ★ 重排是**真的改 items 数组顺序**（不是只在渲染时换个画法）：
       「数组顺序 = 显示顺序」是表格唯一的第一真相，只在渲染时重排的话，
       拖动排序会按视觉落点去算数组下标，一拖就乱。
       代价：日期 / 完成状态一变顺序就变 —— 这正是用户要的那个「自动」。
       触发点：work-core.js 的 `markChanged()`（render 之前）和 `paintData()`（装载时）。
       ⚠ 装载那一遍只重排内存、不 markChanged：只是把顺序摆正，
         不必为此白写一次 OSS。
    6.3.6 连带影响：`items[].manual` 是新增字段（只有手动拖过的才写，
       和 pinned 一个规矩）；老的 plan.json 里没有它，读进来就是 false。
    6.1 「只看」这个状态**会记住**：按 F5 刷新后还在只看模式（名单存在浏览器里，
        每台电脑各自记一份）。觉得碍事就点那个「✕ 看全部」，或者清掉浏览器
        localStorage 里的 safemonitor:work:filter。
    7. **从今天连到工作日的细线**（像甘特图那种）：
       · 有责任人、且**没完成**的安排才画线（打了「已完成」钩，线就没了）；
         **超期未完成也画**，方向反过来 —— 从工作那天连回今天，一眼看出拖了几天；
       · 线的颜色 = 责任人牌子的颜色，高 2px；
       · **同一行里所有线各自占一条轨道**：一个工作项目一行里可能有好几条安排要画线
         （不同日期的两项活、一格多人的、日子在时间轴外面的），
         它们从上到下按「2px 线 + 13px 间距」排开、整叠在行高里居中，
         不会叠在一起看不清；一格多人时主责任人（第一个）在该组的最下面；
       · 两端都不进格子：从「今天」那一格的**右边界**拉到工作那天那一格的**左边界**
         （超期的是从工作那格的右边界拉到今天的左边界），只接在边框上；
         所以紧挨着的两天（中间没空隙）不画线；
       · 整叠线在这一行的**高度中间居中**；
       · 相隔 **≥ 3 天**的（前后都算），在整条线的中点标上应该完成的日期（月/日）：
         不带底色、14px 加粗、压在线上；**点这个日期可以直接编辑那条安排**；
       · 线只是看的，不挡点格子。
    8. 日期如果改到**时间轴范围以外**（比最后一天还晚、或比第一天还早）：
       数据照存不误，只是表格里没有那一格，于是把线画到**最边上的那一格**
       （一直拉到格子边界），点线上的日期牌就能再改回来或删掉。
    9. **删责任人**：工具栏最右边「⋯ → 🗑 删除责任人」，弹层里点名字后面的 ✕ 即可。
       他名下还有安排的话会先问一句；确认后那些安排里他的名字会一起去掉
       （那格只剩内容就保留，变成空的就跟着删）。
    10. **工作查询**：责任人那一排**左边有个「🔍 工作查询」小框** ——
        把某个人的名字牌子拖进这个框，下面整个表格区域就换成他的工作清单：
        · 先一句文字汇总：共几条安排、已完成 / 今天 / 逾期未完成 / 待办各几条、附件几个；
        · 再一张表，列顺序：**日期+星期 / 状态 / 工作项目 / 内容 / 相关文件 / 详细内容**
          （每个附件单独一行，点开可看；前面几列是定宽的，「详细内容」占掉剩下的宽度，
          宽屏时会把屏幕铺满；窗口很窄时整表最窄 1180px，不够就横向滚动）；
        · **排序分四层**（叠在一起看最要紧的）：
          ① 逾期未完成的最上面 ② 待办（今天及以后、没完成）
          ③ 今天以后已完成的 ④ 今天之前已完成的沉到最下面；
          每层里再按日期先后排；
        · 右上角有**日期范围**（两个日期框，进去时默认填好这个人安排的最早~最晚一天），
          改了就重新列一遍；点「全部」= 不限日期；
        · 刚进这个界面时会自动滚到最左边、最上面；**点「← 返回表格」回去时，
          会自动回到你进来之前看的那一天、那个位置**（不会卡在最左边）；
        · 点右上角「← 返回表格」就回到日历（**再点一下那个「工作查询」小框**也行）；
        · 表格字号 16px（表头 15px 加粗）；
        · 查询只是查看，不改任何数据；它和「只看」互斥，进查询会自动取消只看。

九、调整工作项目的上下顺序
    1. 鼠标按住某一行最左侧的 ⠿ 把手，上下拖，松手就换位置；
       光标在上半行 = 插到这行前面，下半行 = 插到这行后面，松手前会有一条黄线提示；
    2. 顺序就是 plan.json 里 items 数组的顺序，会自动上传 OSS，下次打开还是这个顺序；
    3. 新增的工作项目（点「＋ 工作项目」）直接排到**第一行**，方便马上给它排日子；
       名字已经预填好「工作A001」这种编号（从 A001 一路排到 Z999，跳过用得上的编号，
       而且会自动全选，直接打就换掉），不想用编号直接改名字就行。

八、工具栏
    常用的在外面：◎ 回到今天 / ▤ 日历模式 / ▤ 空白行 / 👤 责任人 / ☀ 亮色 / ⌂ 返回首页；
    ＋ 工作项目、导出 CSV、导出 JSON、导入 JSON、重新载入、更新节假日、
    编辑责任人样式、删除责任人 都收在最右边「⋯」里
    （新增项目不常用，放进去腾出工具栏；导入导出这些更是平时用不到）。
    · 「👤 责任人」= 开合工具栏上方那一排责任人的开关（默认收起）；
    · 「☀ 亮色 / ☾ 暗色」= 切换亮/暗模式，记在浏览器里；
    · 「⌂ 返回首页」= 回到轮播页（../index.html），单独开标签打开时也好用；
    · 「▤ 日历模式」= 换成月历看安排，按钮会变成「▦ 表格模式」，详见第十三节。
    · **「▤ 空白行」= 首行那条新工作占位的开关**（2026-09-21 加，**默认关着**；
      自己点开一次以后就一直记着），详见第 8.4 小节。
    · **「⋯ → ⤓ 导出 CSV」（2026-09-21 加）**：把安排导成**一行一条的扁平表**
      （表格那种「日期做列」的矩阵在 Excel 里不好使），列顺序：
        日期 / 星期 / 工作项目 / 内容 / 责任人 / 状态 / 详细内容 / 附件
      （状态和「工作查询」一个口径：已完成 / 逾期未完成 / 待办；多个责任人 / 多个附件用、隔开）。
      导出的范围**跟着当前筛选走**，和屏幕上一致：
        · 开着「工作查询」→ 只导那个人的（并且只在他那个日期范围内）；
        · 开着「只看」→ 只导选中那几个人的（文件名也是他们的名字）；
        · 日历模式没有筛选，就导全部（文件名「工作计划_全部_日期.csv」）。
      实现：`work-io.js` 的 `exportCsv()` / `downloadCsv()`。
      ⚠ `downloadCsv()` 开头**必须加 BOM（\uFEFF）**，否则 Excel 打开中文全是乱码；
        换行用 \r\n；每个单元格都套双引号（里面的双引号翻倍），
        这样内容里的逗号、换行（详细内容里常有）都不会错位。
    工具栏最左边的「OSS 数据」标签平时不显示，只有在用示例数据、
    读不到 OSS 或保存失败时才冒出来提醒。

十、样式约定（以后要改外观先看这里）
    css/work-board.css 是表格层，结构是「父级 → 子级」，从上往下一共 7 段：
      ① 容器 .board-wrap / .board
      ② 吸顶表头 .corner / .col-head（.ch-week .ch-day .ch-hol .ch-flag）
      ③ 行头 .row-head（.rh-grip 拖把手 / .rh-main / .rh-actions）
      ④ 单元格 .cell > .cell-inner（.cell-add .cell-dot .cell-text .cell-owners）
      ⑤ 只看某人（父级开关 .board.is-filtered；别人的行和格子内容是 JS 里直接不画的，
         这里只管「剩下的东西长什么样」：hit = 高亮、hidden = 空格子点不动）
      ⑥ 空表提示  ⑦ 小屏适配
    两种状态写法，别混用：
      · 内容状态 → 写在 data-state 里，空格分隔，CSS 用 [data-state~="xxx"]
        可选值：col-head: weekend/off/makeup/past/today
                row-head: （无）
                cell:     weekend/off/makeup/past/today/task/owner/done/overdue/hit/hidden
                  （done = 这条安排完成了：内容压淡 + 上面那行小圆点旁边跟一个绿色
                   「（已完成）」标记，**不用删除线**；样式在 work-board.css 的 .cell-done）
                cal-day:  weekend/off/makeup/today/past
                cal-task: done/pin/overdue
                  （cell 的 hidden = 「只看某人」时别人那条安排占的位：内容不画、点不动；
                    hit = 这个人的安排，高亮；
                    weekend / off / makeup = 双休日 / 法定放假 / 调休上班，和日历模式同一套；
                    cal-task 的 done = 这条安排已完成（绿色虚线框）、
                    pin = 它所属的工作项目置顶（紫色实线框 + 淡粉底，
                    两个同时成立时实线优先））
    双休日 / 法定节假日怎么写底色（2026-09-21 加的，表格和日历一样的颜色）：
      · 双休日 = 淡绿，法定放假 = 淡粉（2026-09-21 用户要求「用亮一点的粉色」，
        原来是大红），调休上班（补班）= **不染色**（跟工作日一样），
        补班那天只靠表头上那行「国庆节调班」认出来；
      · 颜色**直接写在对应规则里**（没有做成变量）：
        work-board.css 的 .col-head[weekend|off] / .cell[weekend|off]、
        work-calendar.css 的 .cal-day[weekend|off]；亮色模式整条覆盖在 work-light.css。
        想整组换配色得有心理准备：这两个文件 + work-light.css 一共四五处都要改
        （2026-09-21 试过改成「藏青 + 绛红」并抽成 --wk-* 变量，用户觉得不如原配色，已还原）；
      · 表格列头的星期用的是**全写**（「星期一」，JS 里是 work-core.js 的 WEEK_FULL），
        字重 **600**（比正文粗一点，但不到 700，用户说 700 太粗），
        颜色跟正文一致：**深色模式用 --text（略带蓝的 #bed3ff）、亮色模式黑字**；
        周末不再单独压暗 —— 所有星期长一样；
        其他地方（左上角「今天 … 周一」、弹层标题、工作查询表）还是用短写 WEEK_LABEL；
      · ⚠ 表格里这些格子/表头是用 **background-image 叠一层渐变色**，不是 background-color。
        因为 `background: xxx` 这种简写会连 background-image 一起清掉 ——
        所以 .cell:hover / .cell[past] / .cell[today] 都得写 background-color，
        这样「周末的绿 + 过去日的暗底」两层才能同时看见。改这几条时千万别改回简写。
      · 临时交互态 → 才用 class：is-drop-target（拖名字到格子）、
        is-dragging / is-drop-before / is-drop-after（行头拖动排序）、
        is-panning（正在拖表头横向滚屏）
      · 父级开关：.board.is-filtered（正在「只看某个人」）
    所以往格子上加新样式时，先看 data-state 里有没有现成的值，
    不要新加一堆 class —— 结构在 js/work-board.js 的 cellHtml/rowHeadHtml 里生成。

十一、鼠标拖动速查
    · **日期表头**：按住最上面那一行（星期日/星期一 …… 09/20 那一行）左右拖 → 表格跟着横向滚动，
      效果跟拖底部滚动条一样（鼠标按住时是抓手，不会选中文字）；
    · **行头 ⠿**：按住项目名左边的把手上下拖 → 调这一行工作项目的位置（第 9 节）；
    · **责任人牌子**：从工具栏上方那一排拖到某个日期格子上 → 给那天排活（第 7 节）。
    注意：表头只能左右拖（横向滚动），上下滚动还是用鼠标滚轮/滚动条。

十二、详细内容与相关文件（2026-09-21 起都在「填安排」弹层里）
    1. **不再有单独的「📄 详细 / 文件」弹层了**：用户要求「添加新工作直接用一个大一点的对话框，
       不要另外再点一次详细说明的按钮。逻辑和弹窗大小参考 check 里面编辑问题这个弹窗」，
       所以现在点格子打开的就是那个大弹层（`size: 'xl'`，宽 1488px，
       和法定自查的「编辑问题」同一个规格，里面整套字号也跟着放大）。
       实现：work-edit.js 的 `openTaskEditor()`；
       老的 `openDetailEditor()` **已删**，附件的上传/画列表/去掉那套搬到了
       `work-io.js` 的 `bindFileBox()`（和 check-core.js 那个同名函数一个思路）。
    2. 弹层里从上到下：
       · **年 / 月 / 日** 三个小框（只改「日」的时候点进去会自动全选）；
       · **这天要做什么**：表格/日历里格子上显示的那句话；
       · **详细内容**：大输入框（`.tall`，最少 200px 高），写具体做什么、怎么做、做到什么程度；
       · **相关文件**：见下面第 3 条；
       · **责任人牌子**（有的话）+ **已完成** 勾。
       全部由底部那一个「保存」一起写回；直接关掉的话这次改的都不算；
    3. 「相关文件」这一块：
       · 点「选择文件」可以一次选多个，或者**直接把文件拖到虚线框里**；
       · 文件是**免密钥直传到 OSS** 的 SafetyAudit/文件/ 下面，
         文件名前面自动加时间戳（20260920-0730-审核计划.pdf），不会互相覆盖；
       · 传完会列在下面，点文件名可以在新窗口打开/下载，后面显示大小；
       · 点 ✕ 只是**从这条安排里去掉**，OSS 上的文件不会被删（想彻底删要用 ossbrowser）；
       · ⚠ **上传是立刻的（PUT 到 OSS），但要点「保存」才挂到这条安排上** ——
         跟法定自查那边一个规矩。好处是保存前能看到传了哪些、也能去掉传错的；
         传了一半点「取消」，文件已经在 OSS 上了，只是这条安排里不显示而已
         （和清掉一个附件不保存是一回事）；
       · **图片附件的链接上停一下，会浮出图片本身**（jpg / png / gif / webp / bmp / svg 都认），
         工作查询表里和弹层的附件列表里都一样；非图片的附件不会弹；
    4. 格子上会有小记号，鼠标不用点就能看个大概：
       · 右上角 **📄** = 有详细内容，**📎3** = 有 3 个附件（两个都有就两个都标）；
       · **鼠标在格子上停一下**，会浮出一个小窗显示：标题 + 详细内容（换行保留）+ 附件名单，
         移开、滚表格、按下去就收起来；
       · 点开这个格子（那个大弹层）里就是完整的详细内容和附件列表，
         点文件名直接在新窗口打开，上传/去掉也都在这里做。
    5. 这些内容都存在 plan.json 的 tasks[].detail / tasks[].files 里，换台电脑打开都在。

十三、日历模式（▤）
    1. 工具栏点「▤ 日历模式」，表格区域就换成月历 —— 同一份安排，换一种看法。
       按钮会变成「▦ 表格模式」，点它回去；月历右上角也有「← 返回表格」。
    2. 月份随便翻：‹ 8 月 / 今天 / 10 月 ›（按钮上直接写着上、下个月的月份），
       进来自动落在今天所在的那个月；日历模式下工具栏的「◎ 回到今天」= 跳回今天那个月。
    3. **一屏同时看到三个月**：左边一栏上个月、中间当前月、右边下个月，
       每一栏都是**完整自然月**（1 号到月末，前面按「1 号是周几」空几格，不互相借日子）。
       中间那一栏加了框、标题是金色，翻月时一眼知道在看哪个月；
       每栏标题右边还写着这个月有几条安排。
       屏幕不够宽（≤ 1180px）会自动改成竖着排：上月 → 本月 → 下月。
    4. 每个日期格子里：

    8.4 ⚠ **在输入框里用鼠标框选文字，弹层会自己关掉（2026-09-21 已修）**：

       问题出在：在输入框里按下、拖出卡片再松手时，浏览器会把 click 派发给
       **「按下点和松开点的共同祖先」**，也就是弹层背景 —— 于是弹层莫名其妙自己关了，
       看着像「闪退」（其实只是弹层没了，东西没丢）。
       现在改成**按下和松开都在背景上**才算点背景：
       mousedown 记一个 `downOnBackdrop`，mouseup 时两个条件都成立才 closeModal。

       教训：凡是用 `e.target === 容器` 实现「点空白处关闭」，都要同时看 mousedown 的目标。
